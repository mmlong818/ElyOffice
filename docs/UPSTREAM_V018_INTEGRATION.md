## 范围 | Scope

This candidate starts from the public fork's `origin/main` at `1b6b57be67631087aab2a2578f3b4ce3fe6aff45` and integrates the original author's migrated repository by real Git ancestry, fixed at [`main` commit `0d991e1c715859abd1282981fd46989e7e2319c7](https://git.zacharyzhang.com/ZacharyZhang-NY/ElyOffice/commit/0d991e1c715859abd1282981fd46989e7e2319c7). ## 整合取舍 | Integration decisions

- 跟随上游将 ElyMark 切换为原生 Rust/GPUI 编辑器，移除已弃用的 CEF 网页内容 crate、获取脚本和网页打包路径；同时删除旧的 `scripts/build-suite-windows.ps1` 与 `scripts/assemble-suite-windows.ps1`。`packaging/stage.sh` 保留 Windows/Linux ElyMark 需要的 Git 运行文件。保留上游逐文件清单和升级回滚流程，不恢复旧的通配递归删除。新增共享路径校验，拒绝绝对路径、冒号、不安全组件和保留设备名；完整预检清单后才移动文件，并拒绝既有 `.ely-old` reparse point。ASCII 隔离 harness 通过：成功 rollback 保留调用方 blocker，rollback 冲突返回新错误并保留备份。生产安装脚本和 harness 均编译通过，harness 运行通过。真实 UTF-8 中文清单在当前 NSIS `FileRead` 下按系统 ACP 解码成乱码并 fail-closed；本轮未迁移读取编码。安装脚本测试中的 `libcef.dll` 仅作为旧安装清理测试样本保留。
- Windows LibreOfficeKit worker 保留 fork 的 Windows owner 线程、串行 stdin reader、Job Object 监督、deadline、profile quarantine、严格 RESULT receipt 与 callback pins。回调仍保留上游新增的桌面辅助事件分支。上游 TURN 现在通过一个 owner closure 读取/设置当前 part，并保留 i64 IPC 回复；翻页使用原有 LibreOfficeKit slots。
- 保留中英双语产品 README、六个产品应用介绍及 `ORIGIN.md` 中的原作者、X、LibreOffice 和许可归属。README 的“尚无 Windows 安装包或二进制版本”仍描述公开 fork 的发布状态，上游下载不会被描述成本 fork 发布。
- 上游新增的 PDF shim 随源码整合。为 ElyMark 单测，使用既有 MuPDF/OpenSSL stage 和头文件在本地链接了候选 PDF worker（SHA-256 167A556292681595EF6B00AA06E5AD4BBE3E216EC1644CA15983CB4A5D84DC23）。build.rs 将已有的 shim/ely_pen.c 纳入实际 C source list，修复其 7 个未解析符号。没有重建 MuPDF/OpenSSL 原生库，也没有生成安装器或发布二进制。

- ElyMark follows upstream's native Rust/GPUI editor. The retired CEF web-content crate, fetch script, and web packaging path were removed, as were the old `scripts/build-suite-windows.ps1` and `scripts/assemble-suite-windows.ps1`. `packaging/stage.sh` retains the Git runtime needed by standalone ElyMark on Windows and Linux. The installer keeps upstream's per-file ownership manifest and upgrade rollback; the former wildcard recursive deletion was not restored. A shared path validator rejects rooted paths, colons, unsafe components and reserved device names. The complete manifest is preflighted before files move, and an existing `.ely-old` reparse point is rejected. The isolated ASCII harness passed: a successful rollback preserves the caller blocker, and a rollback collision returns the new error while keeping the backup. Both the production installer script and harness compiled, and the harness passed. A real UTF-8 Chinese manifest is decoded as system-ACP text by the current NSIS `FileRead` and fails closed; this task did not migrate the file-reading encoding. `libcef.dll` remains only as a legacy-install fixture in installer tests.
- The Windows LibreOfficeKit worker retains the fork's Windows owner thread, serial stdin reader, Job Object supervision, deadlines, profile quarantine, strict RESULT receipts, and callback pins. The upstream desktop-assistance event branches remain. Upstream TURN now reads and sets the current part in one owner closure and keeps the i64 IPC reply; navigation uses existing LibreOfficeKit slots.
- The bilingual product README, six product application descriptions, and attribution to the original author, their X account, LibreOffice, and the applicable licences remain. The README's statement that this fork has no Windows installer or binary release describes this fork's publication state; upstream downloads are not presented as fork releases.
- Upstream PDF shim sources are included. For ElyMark unit tests, a candidate PDF worker was linked locally against the existing MuPDF/OpenSSL stage and headers (SHA-256 167A556292681595EF6B00AA06E5AD4BBE3E216EC1644CA15983CB4A5D84DC23). build.rs now includes the existing shim/ely_pen.c in the actual C source list, resolving its seven missing symbols. MuPDF/OpenSSL were not rebuilt; no installer or release binary was produced.
